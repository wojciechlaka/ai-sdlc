## Architecture

**Refinement Engine** — guides tickets through stages of the Anthropic *AI-Native SDLC Playbook*:
stage 1 **Plan** (raw ticket → `intent.md`) and stage 2 **Design** (intent → `spec.md`). A Claude agent writes
the artifact, the app commits it to its own branch in the target repo and opens a PR; **merging the PR is the
gate** that moves the ticket to the next stage. Content lives in Git; the app keeps only stage, state,
references and a log per ticket. Stage 1 runs end to end; stage 2 (Design) is modelled but not startable yet
(`STARTABLE_STAGES` in `domain/rules.ts`).

npm workspaces monorepo, Ports & Adapters (hexagonal):

```
apps/web/          Next.js App Router — driving adapter: Server Components (read), Server Actions (write),
                   app/api/events/route.ts (SSE), instrumentation.ts (startup + 60 s review sync timer).
                   lib/container.ts = composition root (engine singleton on globalThis)
packages/core/     domain/ (pure rules, naming, Markdown rendering), ports/ (interfaces),
                   application/ (use cases), adapters/ (sqlite, github, markdownTickets, git, claudeCli,
                   nodeEvents), compose.ts (createRefinementEngine wires real adapters)
packages/shared/   Zod contracts: DTOs, inputs, TicketEvent, agent output (IntentSchema; RefinementOutputSchema for stage 2)
examples/tickets/  simulated Jira tickets — the only ticket source (`# CB-3: Title`, text, `**Priorität:** …`)
```

Dependency direction: `web → core → shared`. `domain/`, `ports/`, `application/` must not import `adapters/`,
`compose`, or I/O modules (fs, child_process, path, os, crypto, drizzle, @octokit, …) — enforced by
`packages/core/eslint.config.mjs`.

Note: `apps/web` uses Next.js 16, which has breaking changes versus older versions. `apps/web/AGENTS.md`
(generated by `next dev`) points to the bundled docs in `node_modules/next/dist/docs/` — read them before
changing Next-specific code.

### Model

- **Ticket** — key `CB-3` (primary key, from the source file), title, description, priority, sourcePath,
  `stage: plan | design | done`, `state: ready | running | awaiting_answer | in_review | failed`
- **AgentRun** — per ticket and stage; `seq`, trigger `initial | answer`, input (model + Q&A history), output, cost/tokens
- **Artifact** — stage, path `docs/work/<KEY>/intent.md|spec.md`, branch `<KEY>/intent|spec`, PR number/url/state, mergedAt
- **AuditEvent** — the per-ticket log shown on the ticket page (`ticket_imported`, `run_started`, `run_finished`,
  `question_asked`, `answer_given`, `pr_opened`, `pr_merged`, `pr_closed`, `stage_changed`, `cleanup`, `error`).
  `apps/web/lib/logFormat.ts` reads these payload keys — keep both in sync.

### Transitions (`domain/rules.ts`)

```
<stage>/ready|failed --start--> running
running --question--> awaiting_answer --answer--> running
running --result (file + branch + PR)--> in_review
in_review --merge--> next stage/ready        (design --merge--> done)
in_review --PR closed--> ready               (branch deleted)
running --error/timeout--> failed
running|awaiting_answer --stop--> ready
```

### Flow ("Plan starten")

1. `startStageAction(key, { model })` → use case `startStage` (`application/stageCommands.ts`): validates (Zod),
   requires a code host (token), sets `running`, creates the AgentRun synchronously (`beginRun`) and hands
   `runStage` to `runInBackground`
2. `runStage`: `RepoProvider.ensureRepo(TARGET_REPO)` (plain clone/pull into `$REPO_CACHE_DIR`, no token) →
   `ensureSummary` → `executeRun`
3. `AgentRunner.run` (`adapters/claudeCli`) picks skill + schema per stage (`STAGE_AGENTS`: plan →
   `skills/intent-agent.md` + `IntentAgentOutputSchema`), spawns `claude --print --output-format stream-json`,
   validates, retries once on schema errors
4. Question → `awaiting_answer`; `answerQuestion` starts a new run with the Q&A history. Intent → `renderIntent`
   → `publishArtifact`: delete leftover branch, create branch, commit file, open PR → artifact + `in_review`
5. `syncReviews` (timer every 60 s, and on every ticket page view) reads PR state: merged → next stage; closed → ready
6. Events reach the browser via `GET /api/events?ticketKey=` (ticket page) or `GET /api/events` (board);
   clients call `router.refresh()` on state/question events

**Attempt identity:** every background step checks `isCurrentRun` (`application/beginRun.ts`: ticket still
`running` and this run is its latest). Stop, restart and reset therefore never let a stale job write state;
a PR opened by a stale attempt is closed again.

### Startup (`application/startup.ts`, also run by `resetSystem` after clearing the DB)

The app works against the base branch `showcase`, not the default branch (`master` stays untouched): PRs target it,
stages and content are read from it, links point to `blob/showcase/…`. Tag `showcase-base` marks its initial state
(names in `compose.ts`, `SHOWCASE_BRANCH`/`BASELINE_TAG`).

`startup(deps, { resetRepo })`: end interrupted runs → import `examples/tickets/*.md` (upsert by key) → without
token: warn and stop. With token: `prepareBaseBranch` (missing tag → head of the default branch; missing
`showcase` → the tag) → `syncReviews` (merges during downtime, also before a reset) → close open PRs of the
app (head branch `<KEY>/intent|spec` of a known ticket, own repo only) and delete their branches → with
`resetRepo` only: delete `<KEY>/intent|spec` of all known tickets, force `showcase` back to `showcase-base` →
derive stage from files on `showcase`. GitHub errors are logged and returned as `{ warnings }`; the app continues
with the DB state. `resetSystem` (reset button) always runs with `resetRepo: true` and shows the warnings;
a restart resets the repo only with `RESET_ON_START=true`. While `resetSystem` runs, `deps.resetState.resetting`
makes `startStage`/`answerQuestion` throw a `ConflictError`.

### Key modules

- `packages/core/src/application/createUseCases.ts` — the `UseCases` interface every adapter uses
- `packages/core/src/application/{stageCommands,runStage,executeRun,publishArtifact,beginRun,syncReviews,startup,queries}.ts`
- `packages/core/src/domain/{rules,artifacts,render,ticketKey}.ts` — transitions, names/paths, Markdown, key ordering
- `packages/core/src/domain/errors.ts` — `NotFoundError`/`ConflictError`/`ValidationError`; adapters check
  `errorCode(err)`, never `instanceof` (Next.js may duplicate modules across bundles)
- `packages/core/src/ports/codeHost.ts` + `adapters/github/githubCodeHost.ts` — GitHub via Octokit (15 s timeout,
  `CodeHostError` with user-facing German messages); base branch, `prepareBaseBranch`, `resetBaseBranch`
- `packages/core/src/adapters/sqlite/schema.ts` — Drizzle schema: `tickets`, `agent_runs`, `artifacts`, `audit_events`
- `packages/core/src/testing/fakes.ts` — in-memory repositories, `FakeCodeHost` (GitHub-like semantics),
  `FakeTicketSource`, `FakeAgentRunner` (`hold()`/`stop()`), `createTestContext({ token })`, `seedTicket`
- `packages/core/skills/intent-agent.md` — stage 1 skill, included verbatim in the prompt
  (`refinement-agent.md` is kept for stage 2)

### Adding things

- **New use case**: function in `packages/core/src/application/`, add it to `UseCases` in `createUseCases.ts`,
  test with `createTestContext()`
- **New DB column/table**: `adapters/sqlite/schema.ts`, `npx drizzle-kit generate` in `packages/core`, extend the
  port + both implementations (SQLite and in-memory fake)
- **New stage agent**: skill file in `packages/core/skills/`, output schema in `packages/shared`, entry in
  `STAGE_AGENTS` (`adapters/claudeCli/index.ts`), add the stage to `STARTABLE_STAGES`
- **New log event**: add the type to `AuditEventType` (`ports/auditLog.ts`) and a line to `apps/web/lib/logFormat.ts`
- **New UI**: `apps/web/components/`; mutations as Server Actions in `apps/web/app/actions.ts` using `runAction`;
  UI primitives in `apps/web/components/ui/` (shadcn/Base UI)
- **New ticket**: Markdown file in `examples/tickets/`; appears after restart or reset

## Prerequisites & Environment

- Node.js 20+, `git`
- `claude` CLI authenticated (`claude login`)
- Runs as one long-lived Node process (`next dev` / `next start`); serverless hosting is not supported (E2)
- Target repo is assumed public; writing (branch, file, PR) needs a fine-grained PAT — setup steps in README.md

Variables in `apps/web/.env.local`:

| Variable                | Default                                                              | Purpose                                     |
|-------------------------|----------------------------------------------------------------------|---------------------------------------------|
| `GITHUB_TOKEN`          | —                                                                    | Writes to the target repo; without it stages cannot start |
| `TARGET_REPO`           | `https://github.com/wojciechlaka/node-express-realworld-example-app` | Target repository on GitHub                 |
| `REPO_CACHE_DIR`        | `$TMPDIR/repo-cache`                                                 | Where the target repo is cloned             |
| `DB_PATH`               | `apps/web/data/refinement.db`                                        | SQLite file path                            |
| `REFINEMENT_TIMEOUT_MS` | `600000` (10 min)                                                    | Max Claude subprocess runtime               |
| `RESET_ON_START`        | —                                                                    | `true`: every start resets `showcase` to `showcase-base` |
